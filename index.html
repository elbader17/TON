Tool Orchestration Node.

El primer framework de Go diseñado exclusivamente bajo el paradigma AI-First. No construido para la ergonomía humana, sino para la predecibilidad extrema de los LLMs.

El Motor de la Singularidad

TON es el "Taller" de ejecución para Singularity, un servidor MCP (Model Context Protocol) diseñado para gestionar agentes y sub-agentes de Inteligencia Artificial de forma masiva.

A diferencia de los frameworks web tradicionales (Gin, Fiber, Echo) que buscan simplificar la vida del desarrollador humano mediante "magia" e inyección dinámica, TON abraza el determinismo estricto. Cada herramienta, cada error y cada estructura está diseñada para que un LLM entienda el contexto de ejecución sin ambigüedades.

Reglas Estrictas de Diseño

Paradigma AI-First

01. Cero Magia

Prohibido el uso de reflect. Todo es estático, explícito y comprobable en tiempo de compilación para garantizar la predicibilidad de la IA.

02. Segregación Extrema

Interfaces con un solo método (ej. UserCreator). Prohibidas las interfaces monolíticas. Contratos claros para agentes.

03. I/O Estructurado

Comunicación entre capas mediante Structs de Request/Response. Adiós a los map[string]interface{} genéricos.

04. Errores Deterministas

Errores tipados (ej. ErrNotFound). Cada error devuelto provee contexto semántico útil para la telemetría del agente.

05. Orientación a Tools

Cada pieza de lógica de negocio en TON está encapsulada para exponerse como una "Tool" nativa consumible por el servidor MCP Singularity, minimizando el gasto de tokens al pasar el esquema de ejecución al LLM.

Topología

La estructura de directorios es inmutable. No se permite crear carpetas fuera de este estándar sin autorización de la arquitectura core.

  • /cmd/ton

    Punto de entrada principal.

  • /internal/domain

    Entidades core y contratos.

  • /internal/tools

    El corazón de TON. Casos de uso como herramientas.

  • /internal/orchestrator

    Enrutamiento hacia /tools.

  • /pkg/errors

    Errores deterministas.

  • /pkg/telemetry

    Trazabilidad para la IA.

Implementación Estricta

ton/internal/tools/ping.go 
package tools

import (
    "context"
    "https://github.com/elbader17/TON/internal/domain"
    "https://github.com/elbader17/TON/pkg/errors"
)

// PingRequest define los parámetros de entrada estrictos para la herramienta.
type PingRequest struct {
    AgentID string `json:"agent_id"`
    Message string `json:"message"`
}

// PingResponse define la salida estructurada esperada por el LLM.
type PingResponse struct {
    Status    string `json:"status"`
    Timestamp int64  `json:"timestamp"`
}

// PingExecutor es el contrato de un solo método (Segregación Extrema).
type PingExecutor interface {
    Execute(ctx context.Context, req PingRequest) (PingResponse, error)
}

type pingTool struct {
    // Inyección de dependencias estática sin reflexiones
}

func NewPingTool() PingExecutor {
    return &pingTool{}
}

func (t *pingTool) Execute(ctx context.Context, req PingRequest) (PingResponse, error) {
    if req.AgentID == "" {
        // Error determinista con contexto para la IA
        return PingResponse{}, errors.NewErrValidation("agent_id es requerido para el ping")
    }

    return PingResponse{
        Status:    "ACK",
        Timestamp: domain.Now().Unix(),
    }, nil
}
