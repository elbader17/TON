La Unidad Motorizada de la Singularidad

En la era de los agentes autónomos de IA, la infraestructura web clásica está desfasada. Las APIs tradicionales inyectan magia dinámica en ejecución, confundiendo la inferencia de los LLMs.

TON (Tool Orchestration Node) es el entorno de ejecución determinista definitivo para el servidor de contexto Singularity. Excluye de forma total las complejidades interpretativas. Cada contrato, respuesta, error de validación e incluso comandos dentro de su Sandbox aislado se definen mediante tipado estricto.

Reglas Estructuradas de Diseño Core

01. Cero Magia

Prohibido el uso de reflexión intensiva (reflect) en tiempo de ejecución. Todo es estático, explícito y comprobable en tiempo de compilación.

02. Segregación Extrema

Interfaces estrictamente reducidas a un solo método explícito (ej. PingExecutor). Prohibidas las interfaces monolíticas o ambiguas.

03. I/O Estructurado

Comunicación estricta entre capas mediante structs deterministas de Request/Response. Eliminación de mapas dinámicos o interfaces vacías no explícitas.

04. Errores Deterministas

Tipado exacto utilizando estructuras de error unificadas (ej. TONError). Cada error devuelto provee un contexto semántico óptimo para la IA.

05. Orientación Nativa a "Tools"

Cada segmento de lógica de negocio o funcionalidad se empaqueta como una "Tool" autodescriptiva para el servidor MCP. Esto optimiza el procesamiento de tokens y la toma de decisiones del LLM al ejecutar acciones en tiempo real.

Especificaciones de Arquitectura

Para expandir las capacidades legibles de tu agente MCP, sigue estas convenciones de codificación estricta:

// 1. Define Request/Response en domain/
type MyRequest struct { Input string }
type MyResponse struct { Output string }
// 2. Crea un Executor de firma única en domain/
type MyExecutor interface { Execute(ctx context.Context, req MyRequest) (*MyResponse, error) }

La herramienta execute_in_sandbox ejecuta comandos dentro de namespaces Linux aislados.

  • Seguridad: Bloquea peticiones HTTP salientes con CLONE_NEWNET para prevenir filtraciones de API keys.
  • Restricción: Solo permite variables de entorno configuradas por el array AllowedEnvs.
  • Control: Limita el abuso de CPU por sub-agentes utilizando timeouts explícitos de ejecución.

Los errores tipados de TON aseguran que el LLM sea capaz de capturar errores de contexto y auto-corregir sus argumentos en tiempo real:

ErrCodeValidation Gatillado por argumentos no válidos en Payload.
ErrCodeNotFound Recursos inexistentes o no registrados.
ErrCodeExecution Fallo de ejecución o desbordamiento de Sandbox.
ErrCodeInternal Interrupción de procesos críticos o memoria del framework.
